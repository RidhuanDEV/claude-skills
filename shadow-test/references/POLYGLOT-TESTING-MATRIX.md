## 1. Universal 8-Point Test Matrix (Mandatory for Every Feature/Endpoint)

Regardless of programming language, every automated test suite generated by `/shadow-test` MUST cover:
1. **Happy Path (`200` / `201`)**: Valid input produces expected response contract + expected database/queue state.
2. **Schema & Validation Failure (`400` / `422`)**: Missing required fields, invalid types, negative numbers, invalid enum/email/UUID.
3. **Unauthenticated Access (`401`)**: Missing, malformed, or expired auth token.
4. **Forbidden / Cross-Tenant IDOR (`403` / `404`)**: User A attempting to read, update, or delete User B's or Tenant B's resource.
5. **Resource Not Found (`404`)**: Valid UUID/ID that does not exist in the database.
6. **Idempotency & Conflict (`409`)**: Duplicate unique email/code, double form submission, or stale optimistic lock version.
7. **Boundary & Edge Values**: `0`, `-1`, `MAX_SAFE_INTEGER`, empty array `[]`, Unicode/emoji strings, UTC midnight/month-end dates, decimal precision (`0.1 + 0.2`).
8. **Transaction Isolation & Clean Teardown**: Every test cleans up or rolls back its own state so running the test suite 10 times in a row produces 100% deterministic results.

## 2. Language & Framework Idioms

### A. TypeScript / Node.js (`Vitest` / `Jest` + `Supertest` + `@testing-library/react`)
- **Strict TypeScript**: Zero `any`, zero `as Type` casting in test files! Build strongly-typed factory functions (`createMockOrder(overrides?: Partial<Order>): Order`).
- **Component/Integration Priority**: Test HTTP routes via `supertest(app)` asserting both response JSON and DB state.

```typescript
import { describe, it, expect, beforeEach } from 'vitest';
import request from 'supertest';
import { app } from '../src/app';

describe('POST /api/v1/orders', () => {
  it('creates an order and returns 201 when payload is valid', async () => {
    const res = await request(app)
      .post('/api/v1/orders')
      .set('Authorization', `Bearer ${validToken}`)
      .send({ items: [{ productId: 'prod_01', quantity: 2 }] });

    expect(res.status).toBe(201);
    expect(res.body.data).toMatchObject({
      status: 'PENDING',
    });
  });

  it('returns 422 when quantity is zero or negative', async () => {
    const res = await request(app)
      .post('/api/v1/orders')
      .set('Authorization', `Bearer ${validToken}`)
      .send({ items: [{ productId: 'prod_01', quantity: -1 }] });

    expect(res.status).toBe(422);
  });
});
```

### B. Python (`pytest` + `pytest-asyncio` + `httpx.AsyncClient` / `TestClient`)
- Centralize fixtures in `conftest.py`.
- Use `@pytest.mark.parametrize` for boundary and validation matrices instead of duplicating test functions.
- Wrap DB sessions in a per-test nested transaction (`SAVEPOINT`) that rolls back automatically on teardown.

```python
import pytest
from httpx import AsyncClient

@pytest.mark.parametrize(
    "payload,expected_status",
    [
        ({"name": "Item Valid", "price": 15000}, 201),
        ({"name": "", "price": 15000}, 422),
        ({"name": "Harga Negatif", "price": -500}, 422),
    ],
)
@pytest.mark.asyncio
async def test_create_product_validation(
    async_client: AsyncClient, auth_headers: dict[str, str], payload: dict, expected_status: int
) -> None:
    response = await async_client.post("/api/v1/products", json=payload, headers=auth_headers)
    assert response.status_code == expected_status
```

### C. Go (`testing` + `net/http/httptest` + Table-Driven Subtests)
- Always use table-driven tests (`tests := []struct{...}`) with `t.Run(tt.name, ...)` and `t.Parallel()` where safe.
- Run with `go test -v -race ./...` to catch concurrency data races.

```go
func TestCalculateDiscount(t *testing.T) {
	t.Parallel()
	tests := []struct {
		name      string
		subtotal  int64
		promoCode string
		want      int64
		wantErr   bool
	}{
		{name: "valid 10 percent promo", subtotal: 100_000, promoCode: "HEMAT10", want: 10_000, wantErr: false},
		{name: "negative subtotal rejected", subtotal: -5_000, promoCode: "HEMAT10", want: 0, wantErr: true},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			got, err := CalculateDiscount(tt.subtotal, tt.promoCode)
			if (err != nil) != tt.wantErr {
				t.Fatalf("CalculateDiscount() error = %v, wantErr %v", err, tt.wantErr)
			}
			if got != tt.want {
				t.Errorf("CalculateDiscount() = %v, want %v", got, tt.want)
			}
		})
	}
}
```

### D. PHP / Laravel (`Pest` / `PHPUnit` + `RefreshDatabase`)
- Use `uses(RefreshDatabase::class)` and model factories (`User::factory()->create()`).
- Assert both HTTP response (`assertCreated()`, `assertUnprocessable()`, `assertForbidden()`) and database state (`$this->assertDatabaseHas(...)`).

```php
use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;

uses(RefreshDatabase::class);

it('prevents a user from updating another tenants invoice (403 IDOR)', function () {
    $tenantAUser = User::factory()->create(['tenant_id' => 1]);
    $tenantBInvoice = Invoice::factory()->create(['tenant_id' => 2]);

    $this->actingAs($tenantAUser)
        ->patchJson("/api/v1/invoices/{$tenantBInvoice->id}", ['status' => 'PAID'])
        ->assertForbidden();
});
```

### E. Java / Kotlin (`JUnit 5` + `AssertJ` + `Spring Boot MockMvc` / `Testcontainers`)
- Prefer constructor injection so services can be unit-tested without booting the full Spring context when testing pure domain rules, and use `@SpringBootTest` + `@Testcontainers` for real DB integration tests.

### F. C# / .NET (`xUnit` + `FluentAssertions` + `WebApplicationFactory<Program>`)
- Use `[Theory]` and `[InlineData(...)]` for boundary matrices, and `WebApplicationFactory` for full pipeline integration tests.

### G. Rust (`#[test]` / `#[tokio::test]` + `sqlx::test`)
- Use `#[sqlx::test]` for isolated temporary database tests per test function, and `tower::ServiceExt::oneshot` to test `axum` routers without binding a TCP port.

### H. Dart / Flutter (`flutter_test` + `mocktail`)
- Test widgets by semantic labels/keys (`find.bySemanticsLabel`, `find.byKey`), pump frames deterministically (`await tester.pumpAndSettle()`), and verify state transitions across loading, success, empty, and error states.
