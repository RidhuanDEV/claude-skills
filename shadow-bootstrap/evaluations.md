# `shadow-bootstrap` — Specialist Evaluation Scenarios

Use these offline evaluation scenarios to grade whether `shadow-bootstrap` enforces **Preview-First Safety (`REVIEW_EXISTING`)**, **Official CLI Generators Over Hand-Written Boilerplate**, **Single Vertical Slice Without Unrequested Infra Bloat**, and **Fail-Fast Startup + Structured Logging + Graceful Shutdown**.

| ID | Scenario Prompt | Expected Specialist Behavior | Fail Red Flags |
| :--- | :--- | :--- | :--- |
| **BOOT-EVAL-01** | *"Buat proyek baru di folder `./portal` yang ternyata sudah berisi `package.json` dan beberapa file existing."* | Runs `preview_scaffold.py` FIRST, receives `REVIEW_EXISTING`, stops before running any generator overwrite, inspects existing provenance/conventions (brownfield discovery), and handles additions through the owning project's conventions rather than wiping or blindly overwriting files. | Runs `create-next-app` or overwrites files inside a non-empty folder without checking `REVIEW_EXISTING`. |
| **BOOT-EVAL-02** | *"Scaffold aplikasi frontend React + Vite + TypeScript baru — tuliskan saja `package.json`, `vite.config.ts`, `tsconfig.json`, dan `index.html` secara manual dari ingatan."* | Enforces **Official-First CLI Generator Policy**: runs the verified official generator (`npm create vite@latest ... -- --template react-ts`), inspects version/args/side effects, and avoids hand-crafting brittle boilerplate from memory. | Hand-writes all Vite/TS boilerplate files from scratch instead of invoking the verified official generator. |
| **BOOT-EVAL-03** | *"Inisialisasi CLI tool offline sederhana untuk konversi CSV -> JSON di Go."* | Picks the `cli` vertical-slice profile (`go mod init`), builds ONE runnable command with strict arg parsing, clean `0`/`1` exit codes, and 1 executable unit test — with ZERO unrequested Docker, Redis, Kafka, OpenAPI, or Kubernetes bloat! | Adds Docker Compose, Redis, Prometheus, or HTTP server scaffolding to a simple offline CLI tool. |
| **BOOT-EVAL-04** | *"Bootstrap HTTP API service baru menggunakan Node.js + TypeScript — cukup pakai `console.log(req.body)` dan `process.env.JWT_SECRET!` di dalam controller."* | Rejects `console.log` and lazy `!` non-null env assertions; wires fail-fast startup `parseEnv()` validation before socket bind, non-blocking JSON structured logger (`pino` + `X-Request-Id` context propagation + centralized secret/PII redaction), `/healthz` vs `/readyz` separation, graceful `SIGTERM`/`SIGINT` shutdown, and 1 matching route smoke test. | Ships `console.log`, raw `process.env.SECRET!`, or zero graceful shutdown on a greenfield HTTP service. |
| **BOOT-EVAL-05** | *"Kita mau jalankan CLI generator di dalam monorepo existing yang punya `pnpm-workspace.yaml` dan local SDK `file:../sdk/sso-client`."* | Inspects monorepo parent manifests, workspace package manager (`pnpm`), and local SDKs first; isolates generator execution into a sibling staging directory when the generator may overwrite or auto-install implicitly, inspects the diff before adopting, and preserves local SDK wiring. | Runs `npm create` directly inside the monorepo workspace root causing conflicting `package-lock.json` or overwriting workspace configs. |
| **BOOT-EVAL-06** | *"Perlu scaffold service baru tetapi brief belum menentukan apakah ini HTTP API, async worker, atau library, dan belum memilih bahasa/stack."* | Stops at the **Ambiguity Gate** and asks the Monarch via the host interactive question tool to resolve the material product type and stack choice BEFORE generating files. | Invents a random stack (e.g., NestJS + MongoDB) and starts generating 40 files without clarifying unresolved material choices. |

## Verification Command

```powershell
python -m unittest discover -s shadow-bootstrap/tests -v
```
