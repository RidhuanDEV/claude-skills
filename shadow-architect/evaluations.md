# `shadow-architect` — Specialist Evaluation Scenarios

Use these offline evaluation scenarios to grade whether `shadow-architect` enforces **Right-Sized Engineering (Modular Monolith Default)**, **Clean Module Public Facades**, **Explicit Consistency & Failure Assumptions**, **Brownfield Convention Preservation**, and **Official-First Decision Records** (pair with [evals/decision-trials.md](evals/decision-trials.md)).

| ID | Scenario Prompt | Expected Specialist Behavior | Fail Red Flags |
| :--- | :--- | :--- | :--- |
| **ARCH-EVAL-01** | *"Tim kami berjumlah 3 developer ingin membangun SaaS manajemen klinik + billing; mari kita pecah jadi 7 microservices + Kafka + Kubernetes sejak hari pertama."* | Pushes back candidly against resume-driven complexity: recommends a **Modular Monolith + Async Worker** (`PostgreSQL` + transactional outbox + strict `public.ts` module facades) giving strong domain isolation and ACID consistency at 10% of operational cost, documenting clear quantitative extraction triggers in an ADR. | Cheerfully designs 7 microservices, Kafka, and Kubernetes for a 3-developer early SaaS without proven scaling/team need. |
| **ARCH-EVAL-02** | *"Modul `orders` butuh data status faktur dari modul `billing`, jadi kita langsung `JOIN billing.invoices` di repository `orders` dan import helper internal `billing/internal/tax.ts`."* | Rejects cross-module table joins and internal imports (creates a tangled big ball of mud that breaks independent extraction); enforces a typed **Module Public Facade (`modules/billing/public.ts`)** + ESLint/dependency-cruiser fitness function blocking cross-module internal/DB imports. | Allows direct cross-module table joins or importing `modules/billing/internal/*` for convenience. |
| **ARCH-EVAL-03** | *"Sebuah aplikasi Express MVC legacy yang berjalan rapi di produksi perlu tambah 1 fitur ekspor laporan; sekalian kita migrasi seluruh repo ke Clean Architecture + Hexagonal + CQRS ya?"* | Enforces **Brownfield Convention Preservation** (`codebase_intelligence.py` 10-facet profile & 5-level Convention Precedence): preserves the existing Express MVC architecture, matches 1–3 closest existing module precedents, and refuses unsolicited architectural rewrites! | Proposes migrating the entire working MVC codebase to Clean/Hexagonal Architecture + CQRS unrequested. |
| **ARCH-EVAL-04** | *"Desain arsitektur sistem e-commerce dengan stok terbatas, dompet saldo, pencarian produk, dan analitik dashboard — apakah semua data boleh eventually consistent?"* | Explicitly maps **Consistency & Failure Assumptions**: mandates **strict ACID / serializability** for money ledger, finite inventory, and auth grants, while cleanly placing search index updates and BI/analytics projections on **eventual consistency** (Outbox/CDC) with documented partition/skew behavior. | Applies eventual consistency to wallet balances/limited inventory or fails to distinguish ACID vs eventual boundaries. |
| **ARCH-EVAL-05** | *"Kita mau menambah Redis, Elasticsearch, dan RabbitMQ untuk portal internal 200 user harian supaya 'modern'."* | Runs capacity math (`200 DAU -> < 1 peak RPS`), applies the **Official-First 5-tier hierarchy**, exhausts PostgreSQL built-ins first (indexes, `FTS`/`pg_trgm`, `SKIP LOCKED`), emits an 8-field Decision Record, and asks explicit Monarch approval before adding any extra runtime infrastructure. | Adds Redis, Elasticsearch, and RabbitMQ silently without capacity sizing math or Monarch approval. |
| **ARCH-EVAL-06** | *"Perubahan ini hanya mengekstrak 1 helper lokal di dalam modul `pricing` yang mudah di-rollback; apakah harus membuat 4 diagram C4 dan 5 ADR?"* | Calibrates deliverables proportionally to **decision scope** (`test_boundary_levels.py`): answers reversible module-local changes inline (precedent, transaction boundary, coupling, rollback) and reserves C4 diagrams + formal ADRs for shared contracts, deployment boundaries, or data-ownership shifts! | Produces heavy enterprise bureaucracy (full C4 + 5 ADRs) for a trivial reversible local helper extraction. |
| **ARCH-EVAL-07** | *"Instansi pemerintah butuh blueprint integrasi 14 aplikasi lintas dinas, pemetaan 6-Domain SPBE, dan rasionalisasi portofolio TIME."* | Recognizes scope boundary and routes cleanly to **`/shadow-ea`** (Enterprise Architecture & 6-Domain SPBE portfolio governance) rather than stretching single-application `shadow-architect` across a 14-app government portfolio. | Attempts to handle multi-application SPBE 6-Domain enterprise portfolio rationalization inside single-system `shadow-architect`. |
