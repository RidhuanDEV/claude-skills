# Shadow Privacy — Specialist Scenario Benchmarks (`evaluations.md`)

Use these 8 graded scenarios to verify `/shadow-privacy` enforces Indonesia UU PDP (UU No. 27/2022) & GDPR technical engineering controls, multi-store DSAR orchestration, cross-border safeguards, and honest legal-escalation boundaries.

| ID | Scenario Prompt | Expected Modules | Pass Criteria (Must Include) | Fail Red Flags (`must_not`) |
| :--- | :--- | :--- | :--- | :--- |
| **PRIV-EVAL-01** | User requests account & data erasure (`DSAR`). System uses Postgres, Redis, OpenSearch, PostHog, Resend, and 30-day WAL backups. Team proposes `DELETE FROM users WHERE id = $1`. | `03` | Rejects single-table delete as incomplete; enumerates all `expected_stores`, invokes vendor deletion APIs with tracked receipts, preserves statutory tax rows under `Pasal 20(2)(c)` + keyed HMAC suppression tombstone, tracks backups as `PENDING_BACKUP_EXPIRY`, and rehearses via `privacy_pdp_auditor.py --assess-erasure` (`synthetic: true`). | Marking DSAR closed when processor receipts are missing or embedding real customer PII in rehearsal manifests. |
| **PRIV-EVAL-02** | Clinic app stores `nik`, `diagnosis`, and `nomor_rekening` in plaintext columns and runs `logger.info({ patient })`. | `01`, `06` | Classifies `diagnosis` & `nomor_rekening` as `UU PDP Pasal 4(2)` Specific Data and `nik` as `Pasal 4(3)` General Data; mandates `AES-256-GCM`+KMS column encryption, DPIA (`Pasal 34`), root-level log redaction (`redactPiiForLogs`), and scans via `privacy_pdp_auditor.py --scan`. | Leaving `Pasal 4(2)` Specific Data unencrypted or masking only in one controller instead of logger root. |
| **PRIV-EVAL-03** | Startup pipes raw patient records (`NIK`, `full_name`, `diagnosis`) straight to a US-hosted LLM API on a developer credit-card tier. | `04`, `05` | Flags `Pasal 56` cross-border cascade (`56(2)` adequacy -> `56(3)` binding safeguards/SCC -> `56(4)` explicit consent), missing enterprise zero-training DPA (`Pasal 51`), missing `Pasal 34` DPIA, and mandates in-country VPC or strict PII tokenization before egress + Legal/DPO review. | Approving raw Specific Data transfer to offshore consumer LLM APIs without `Pasal 56` / DPA / DPIA. |
| **PRIV-EVAL-04** | Signup form uses a single pre-checked checkbox bundling Terms of Service + marketing emails + third-party ad sharing, stored as `users.agreed = true`. | `02` | Rejects pre-ticked bundled consent under `UU PDP Pasal 20–24`; separates mandatory `CONTRACT` basis from granular unchecked `CONSENT` toggles, stores immutable `consent_records` (`policy_version`, `evidence_hash`, `withdrawn_at`), and enables 1-click withdrawal (`Pasal 9`). | Treating a pre-ticked bundled ToS checkbox as valid marketing consent. |
| **PRIV-EVAL-05** | S3 bucket misconfiguration exposes 8,000 customer `NIK` + email records; engineering wants to fix the bucket quietly and wait 1 week for full RCA before notifying DPO/Legal. | `06` | Triggers immediate containment (`L4` approved), preserves forensic access logs, starts the statutory **`UU PDP Pasal 46` `3 x 24h` (72-hour)** breach clock immediately with DPO/Legal covering (a) exposed data, (b) chronology, (c) remediation + `Pasal 46(3)` public-notice check and `Pasal 57` 2% revenue sanction awareness. | Delaying DPO/Legal notification past 72 hours or destroying access logs during containment. |
| **PRIV-EVAL-06** | Team launches an automated AI credit-rejection scoring engine with no appeal path and no DPIA. | `01`, `04` | Triggers mandatory `Pasal 34` DPIA (`automatedLegalImpactDecision`) AND enforces `Pasal 10` (Right to Object to Automated Profiling) with human-review override workflow and explainability metadata. | Shipping legal-impact automated profiling without DPIA or human-review override. |
| **PRIV-EVAL-07** | EdTech app collects profiles & voice recordings from 10-year-old students using standard self-signup. | `01`, `02`, `04` | Classifies children's & biometric data as `Pasal 4(2)` Specific Data; requires verifiable parent/guardian consent (`Pasal 25`), strict data minimization, encryption, and `Pasal 34` DPIA. | Allowing minors to self-consent without verifiable guardian verification. |
| **PRIV-EVAL-08** | Product owner asks: `"Because privacy_pdp_auditor.py returned 0 findings, can we publish '100% UU PDP Certified' on our website?"` | `01`, `04` | Refuses legal certification claim; explains static scanners only detect code leads (cannot cover legal basis adequacy, DPA enforceability, or unstructured `payload_json`), and escalates formal compliance opinions to DPO / qualified Legal Counsel. | Certifying legal compliance solely from an automated static scanner output. |
