# `shadow-search` — Specialist Evaluation Scenarios

Use these offline evaluation scenarios to grade whether `shadow-search` operates as a **Search, Retrieval & Ranking Engineering Specialist** (not just a wrapper around `pgvector` or Elasticsearch defaults).

| ID | Scenario Prompt | Expected Specialist Behavior | Fail Red Flags |
| :--- | :--- | :--- | :--- |
| **SRCH-EVAL-01** | *"Pengguna mencari nomor peraturan `PP-27/2022` dan kode SKU `INV-8841-ID` di sistem RAG hukum & katalog berbahasa Indonesia, tetapi hasil top-5 hanya memunculkan dokumen mirip topik umum tanpa dokumen persis tersebut."* | Diagnoses dense-vector exact-identifier blindness; designs dual-field mapping (`keyword` exact/normalized + Indonesian lexical `text` with `ascii_folding`, Sastrawi/Indonesian stemmer, stopword hygiene) fused with dense vectors via Reciprocal Rank Fusion (`RRF`, $k = 60$) and exact-match lexical boosting. | Recommends increasing vector dimensions or lowering cosine similarity threshold alone without adding lexical BM25 + exact `keyword` subfields. |
| **SRCH-EVAL-02** | *"Tim memasang filter `cosine_similarity >= 0.80` agar tidak ada dokumen tidak relevan, namun recall query Bahasa Indonesia slang (`bikin npwp ilang`) turun ke 0%."* | Flags the uncalibrated fixed similarity cutoff anti-pattern; explains why cosine distributions shift across embedding models, languages, and informal queries; builds a held-out graded judgment set (`0..3`) segmented by Bahasa Indonesia informal vs formal queries and calibrates thresholds/RRF cutoffs using `Recall@K`, `MRR@K`, and `NDCG@K` curves. | Suggests arbitrarily nudging the hardcoded threshold from `0.80` to `0.65` without held-out evaluation or query-segment breakdown. |
| **SRCH-EVAL-03** | *"Arsitektur vector search mengambil `top_k = 10` global dari Qdrant/pgvector lalu menyaring `tenant_id` dan `permission_scopes` di layer Node.js."* | Blocks the design as a critical cross-tenant leakage & recall-collapse defect (post-filtering exposes existence via timing/counts and returns empty pages when top-10 belongs to other tenants); enforces pre-top-K filtered search inside the engine (`HNSW` filtered index / partitioned `pgvector` + payload indexes) and verifies via `search_relevance_acl_gate.py`. | Approves post-filtering with a larger `top_k = 50` buffer instead of enforcing pre-top-K ACL filtering in the retrieval engine. |
| **SRCH-EVAL-04** | *"Karyawan keluar dari grup `finance-confidential` pada pukul 10:00, tetapi hasil pencarian dokumen masih menampilkan file sensitif tersebut hingga sinkronisasi batch malam."* | Treats stale ACL revocation as a security/freshness defect; designs near-real-time permission tombstone propagation (CDC/outbox event updating document ACL version or live group-membership principal token lookup at query time) + tombstone verification tests in `search_relevance_acl_gate.py`. | Leaves overnight full-reindex batch sync as acceptable for revoked confidential permissions. |
| **SRCH-EVAL-05** | *"Kita perlu mengganti analyzer bahasa Indonesia dan mengubah dimensi embedding dari `1536` ke `1024` di index OpenSearch produksi tanpa downtime."* | Rejects in-place mapping mutation (impossible/corrupting in Lucene/OpenSearch); specifies zero-downtime blue/green alias reindexing (`docs_v2` creation -> dual-write or CDC catch-up -> backfill -> parity count & paired offline relevance check -> atomic `_aliases` swap keeping `docs_v1` warm for instant rollback). | Recommends deleting and recreating the live index during maintenance or mutating field mapping directly on the serving index. |
| **SRCH-EVAL-06** | *"Endpoint pagination search crash OOM di OpenSearch saat pengguna melompat ke halaman 2500 (`from: 50000, size: 20`)."* | Explains deep-offset coordinator heap explosion (`from + size` across shards); replaces deep `from/size` pagination with `Point in Time (PIT)` + `search_after` tie-breaker (`_score` + unique deterministic `id`) and caps interactive offset depth (`index.max_result_window`). | Raises `index.max_result_window` to `100000` without addressing coordinator heap and shard sorting cost. |
| **SRCH-EVAL-07** | *"Eksperimen reranker baru menaikkan `NDCG@10` rata-rata dari `0.71` ke `0.76`, tetapi segmen exact-SKU turun `-15%` dan latency p99 naik `420ms`."* | Refuses blind promotion on aggregate metrics alone; requires paired query-ID comparison on a frozen fixture with segment breakdown (`segments` in `search_relevance_acl_gate.py`), enforces latency budget gating (rerank only top-20–50 candidates or bypass reranker on high-confidence exact SKU matches), and hands retrieval metrics separately from LLM faithfulness to `shadow-eval`. | Approves shipping the candidate index solely because overall macro `NDCG@10` improved. |
