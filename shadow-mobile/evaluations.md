# Shadow Mobile — Specialist Evaluation Suite

> Offline behavioral evaluation suite for `/shadow-mobile`. Validates OWASP MASVS v2.1.0 storage/crypto/network/platform hardening, merged-manifest inspection vs source-only scans, iOS `PrivacyInfo.xcprivacy` + App Attest, Android 16 KB page-size alignment + Play Integrity + signing hygiene, verified Universal/App Links, and in-place upgrade migration safety.

## Graded Scenarios

| ID | Scenario Prompt | Expected Specialist Behavior | Fail Red Flags |
| :--- | :--- | :--- | :--- |
| **MOB-01** | *"Store our React Native JWT refresh token in `AsyncStorage` and gate the app with `if (await LocalAuth.authenticate()) { setUnlocked(true); }`. Also keep `usesCleartextTraffic="true"` in main `AndroidManifest.xml` so dev servers keep working."* | Rejects all three MASVS violations (`01-owasp-masvs-v21-storage-crypto-network-platform.md`): mandates Keychain (`ThisDeviceOnly`) / Android Keystore with `allowBackup="false"`, hardware-bound `CryptoObject` biometrics + server-validated tokens, and `usesCleartextTraffic="false"` in `src/main/AndroidManifest.xml` (moving localhost HTTP strictly to `src/debug/res/xml/network_security_config.xml`). | Stores tokens in plaintext `AsyncStorage`/`UserDefaults`, relies on client-side boolean biometric checks, or leaves `usesCleartextTraffic="true"` in production manifests. |
| **MOB-02** | *"Prepare our iOS app for App Store Connect. We use `UserDefaults` and file timestamps, offer Google Sign-In, allow in-app signup, and have `NSAllowsArbitraryLoads = true` in `Info.plist`."* | Enforces **iOS App Store Compliance** (`02-ios-app-store-privacy-manifest-and-app-attest.md`): requires `PrivacyInfo.xcprivacy` declaring `NSPrivacyAccessedAPICategoryUserDefaults` (`CA92.1`) & `FileTimestamp` (`C617.1`) + Xcode Privacy Report audit for third-party SDKs, sets `NSAllowsArbitraryLoads = false`, requires Sign in with Apple parity (`Guideline 4.8`), and mandates in-app account deletion (`Guideline 5.1.1(v)`). | Ships without `PrivacyInfo.xcprivacy` (guaranteed `ITMS-91053` rejection), leaves ATS disabled, or omits Sign in with Apple / in-app account deletion. |
| **MOB-03** | *"Our Android release uses `play-services-safetynet`, hardcodes `storePassword = "prodPass123"` in `build.gradle`, and ships a native `.so` barcode library built with NDK r23 targeting Android 15."* | Flags all three release blockers (`03-android-play-console-16kb-signing-and-integrity.md` & `mobile_release_gate.py`): removes hardcoded keystore password in favor of CI env vars + Play App Signing, migrates deprecated SafetyNet to **Google Play Integrity API** with server-side verdict & `requestHash` validation, and requires **16 KB ELF page-size alignment** (`NDK r27+`, `AGP 8.5.1+`, `llvm-objdump` verification on `.aab`). | Retains deprecated SafetyNet, leaves plaintext keystore credentials in Gradle/Git, or skips 16 KB `.so` alignment verification for Android 15+. |
| **MOB-04** | *"Our static scan of `src/main/AndroidManifest.xml` came back clean, so we're ready to sign the `.aab` for Google Play production."* | Applies **Merged-Manifest & Channel Binding Discipline** (`01-owasp-masvs-v21-storage-crypto-network-platform.md`): warns that source-only scans exclude build outputs and merged library manifests from third-party AARs; instructs inspecting the **merged release manifest** (`apkanalyzer` / manifest merger report) and binding findings to exact shipping channel, build variant, and artifact digest. | Declares release security verified solely from scanning unmerged `src/main/AndroidManifest.xml`. |
| **MOB-05** | *"We added a new `NOT NULL` column to our local mobile SQLite database for `v3.0.0`. Fresh-install tests pass on the emulator—ship it!"* | Blocks premature release (`04-deep-links-upgrade-migrations-and-maestro-e2e.md`): requires testing **in-place upgrade from a supported installed version (`v2.x`) containing existing user data** PLUS interrupted-migration recovery (transactional migration / default value), and explicitly documenting whether older live clients remain compatible with the backend API. | Ships a local DB schema migration verified only on fresh installs without upgrade-path or old-client compatibility verification. |
| **MOB-06** | *"Set up Android App Links using our local debug keystore SHA-256 in `assetlinks.json`, and allow any URL passed via `myapp://open?url=...` to load inside our WebView."* | Enforces **Verified Deep Links & Allowlist Hygiene** (`04-deep-links-upgrade-migrations-and-maestro-e2e.md`): replaces debug SHA-256 with the exact **Play App Signing SHA-256** served over HTTPS (`200 OK`, zero redirects), verifies via `adb shell pm get-app-links`, and blocks arbitrary WebView URL loading with a strict HTTPS host + regex route allowlist (`MASVS-PLATFORM`). | Publishes debug keystore fingerprints for production App Links or allows unvalidated open-redirect URLs into an embedded WebView. |
| **MOB-07** | *"Pin our API's current leaf TLS certificate directly inside the mobile app with no backup pin so nobody can MITM our banking API."* | Prevents self-inflicted mobile outage (`01-owasp-masvs-v21-storage-crypto-network-platform.md`): rejects single leaf-certificate pinning (which bricks 100% of installed users on emergency cert renewal) and specifies **SPKI public-key pinning** with an offline backup key pin plus explicit expiration/rotation window. | Hardcodes a single leaf certificate hash with zero backup pin or rotation path. |
