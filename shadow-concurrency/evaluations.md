# Shadow Concurrency — Specialist Scenario Benchmarks (`evaluations.md`)

Use these 7 graded scenarios to verify `/shadow-concurrency` eliminates dual-write races, crash-before-ack duplicates, poison-message spin loops, and unsafe distributed lock assumptions.

| ID | Scenario Prompt | Expected Modules | Pass Criteria (Must Include) | Fail Red Flags (`must_not`) |
| :--- | :--- | :--- | :--- | :--- |
| **CONC-EVAL-01** | Worker sends a transactional email via SMTP, then crashes BEFORE acknowledging the queue job; job redelivers and sends duplicate emails. | `01`, `02` | Rejects false "guaranteed exactly-once raw SMTP" claims; enforces `commit -> outbox -> dispatch -> ack`, idempotent ESP `Idempotency-Key` + durable outbox state machine, and crash-before-ack replay tests. | Claiming raw SMTP can be made "strictly exactly-once" or acknowledging the job before sending. |
| **CONC-EVAL-02** | Checkout API runs `await db.orders.create(order)` followed by `await redisQueue.add('order.created')`; Redis briefly fails and 200 orders never trigger fulfillment. | `01` | Identifies dual-write race; moves event creation into `outbox_events` inside the SAME ACID DB transaction + `FOR UPDATE SKIP LOCKED` lease-reclaim relay worker. | Keeping `db.commit()` and `queue.add()` as two separate uncoordinated calls with only a `try/catch` log. |
| **CONC-EVAL-03** | RabbitMQ redelivers a `PaymentSucceeded` event due to consumer restart, crediting a user's wallet balance twice. | `02` | Implements `inbox_dedup (consumer_name, message_id)` claimed inside the **exact same ACID DB transaction** as the wallet credit (`ON CONFLICT DO NOTHING` -> safe `DUPLICATE_SKIPPED` + `ack`). | Deduplicating in an in-memory JS `Set` or in a separate transaction before the wallet credit. |
| **CONC-EVAL-04** | A malformed JSON payload causes a worker to throw `TypeError`, immediately requeue to the head of the queue, and burn 100% CPU starving all valid jobs. | `03` | Separates transient (`429`/`5xx`/timeout) vs permanent (`400`/schema) failures; routes permanent errors immediately to **DLQ**, caps retries with Full-Jitter exponential backoff, bounds prefetch concurrency, and adds throttled DLQ replay runbook. | Using fixed-delay infinite retries or immediate head-of-queue requeue on schema errors. |
| **CONC-EVAL-05** | Team uses a 10-second Redis `SET NX PX` lock to guard inventory writes; a 12-second GC pause lets a zombie worker overwrite newer inventory data. | `04` | Explains why lease locks alone do not guarantee mutual exclusion under pauses (Kleppmann); enforces **monotonic fencing tokens** checked by storage (`WHERE fencing_token < $token`) or atomic DB conditional updates. | Claiming Redlock / Redis `SET NX` alone is 100% immune to GC pauses. |
| **CONC-EVAL-06** | Delayed retry of `OrderCreated (v1)` arrives AFTER `OrderPaid (v2)` and overwrites the order projection back to `CREATED`. | `02` | Guards consumer upserts/updates with monotonic version check (`WHERE EXCLUDED.aggregate_version > target.version`) so stale out-of-order deliveries are harmless no-ops. | Applying queue events blindly with unconditional `UPDATE` / `ON CONFLICT DO UPDATE`. |
| **CONC-EVAL-07** | A 2-service SaaS handling 20 jobs/minute wants to deploy a 3-node Kafka cluster just to send welcome emails and PDF exports. | `04` | Applies right-sized engineering: recommends PostgreSQL Outbox + `FOR UPDATE SKIP LOCKED` (or existing Redis + BullMQ) over premature Kafka ops overhead. | Recommending Kafka + Debezium + ZooKeeper for 20 jobs/minute without proven scale need. |
