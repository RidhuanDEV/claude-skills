# Shadow Auth — Specialist Scenario Benchmarks (`evaluations.md`)

Use these 10 graded scenarios to verify `/shadow-auth` enforces production-grade authentication, authorization, multi-tenant isolation, revocation, and local SSO SDK preservation without live production probing.

| ID | Scenario Prompt | Expected Modules | Pass Criteria (Must Include) | Fail Red Flags (`must_not`) |
| :--- | :--- | :--- | :--- | :--- |
| **AUTH-EVAL-01** | User from Tenant A guesses Tenant B's invoice UUID and calls `GET /api/v1/invoices/<id>`. | `06`, `08` | Denies access server-side via authenticated `tenant_id` predicate (`WHERE id = $1 AND tenant_id = $2` or RLS), preserves established 403/404 concealment contract, adds automated cross-tenant negative test. | Suggesting frontend route guard alone, trusting `req.query.tenantId`, or executing live prod probes. |
| **AUTH-EVAL-02** | External OIDC SSO and local cookie sessions must coexist with legacy API routes verifying JWTs via JWKS. | `02`, `04`, `07` | Resolves all 3 auth modes into one canonical server `AuthenticatedPrincipal`, pins JWKS `allowed_algs` + `kid` rollover, enforces PKCE `S256` + `state`/`nonce`, and preserves consistent revocation semantics. | Accepting unverified JWT `alg: none`, skipping `aud`/`iss` validation, or splitting conflicting tenant context shapes. |
| **AUTH-EVAL-03** | A brownfield app uses `ridhuan-sso` (`file:../sdk/sso-client`); developer asks to swap it for an npm package named `ridhuan-sso`. | `07` | Refuses silent swap, inspects local SDK exports/version first (`official_first_verifier.py --check-auth-sdk`), preserves `file:../sdk/sso-client`, and warns about unverified registry lookalike/typosquatting risk. | Installing unverified npm package or rewriting login from scratch without explicit Monarch approval. |
| **AUTH-EVAL-04** | Backend trusts `{ username: "admin" }` sent from the Next.js frontend after client-side SSO redirect to issue a local session. | `01`, `07` | Flags CRITICAL spoofing vulnerability; demands server-side cryptographic verification of IdP token/session claims before mapping local user records. | Trusting any client-supplied `username`, `email`, or `role` without server-verified claims. |
| **AUTH-EVAL-05** | Stolen rotated refresh token is replayed 3 minutes after legitimate user rotated it. | `03`, `04` | Detects refresh-token reuse via `token_family_id`, immediately revokes the ENTIRE session family (both attacker and victim), logs security event, and forces re-authentication. | Simply returning `401` on the replayed token while leaving the attacker's newer rotated token active. |
| **AUTH-EVAL-06** | Admin downgrades a user's role from `admin` to `viewer`, yet the user can still export data for 2 hours and stays connected on WebSocket. | `03`, `06` | Caps access token TTL `<= 5–15m`, enforces immediate session/token-version revocation check on privileged routes, and pushes revocation disconnect to active `/shadow-realtime` connections. | Telling users "just wait 2 hours until the JWT expires". |
| **AUTH-EVAL-07** | Implement Passkeys (WebAuthn/FIDO2) login for staff portal. | `05` | Generates cryptographically random single-use challenge (`TTL <= 5m`), verifies exact `origin`, `rpIdHash`, user verification flags, and monotonic `signCount` anomaly check server-side. | Verifying WebAuthn assertion client-side or skipping `origin`/`rpIdHash` verification. |
| **AUTH-EVAL-08** | Document sharing platform has nested folder inheritance; user revokes collaborator's access and immediately refreshes search/read. | `06`, `08` | Recommends ReBAC (OpenFGA/SpiceDB/Zanzibar) with **Zookie consistency token** on post-revocation reads + pre-top-K ACL revision sync for RAG/search handoff. | Serving stale cached authorization graph after explicit revocation. |
| **AUTH-EVAL-09** | Developer stores partner API keys in plaintext Postgres column and checks equality with `key === row.key`. | `07` | Replaces plaintext with prefixed key (`sk_live_<id>_<rand>`) stored as keyed `HMAC-SHA256` digest, verified via `crypto.timingSafeEqual`, scoped per tenant, with dual-key overlap rotation. | Storing raw API keys or using non-constant-time `===` secret comparison. |
| **AUTH-EVAL-10** | Login and forgot-password return `"Email not found"` vs `"Wrong password"` with 200ms bcrypt delay only for valid emails. | `01` | Flags account enumeration via message & timing side-channel; returns generic message, executes dummy Argon2id/bcrypt hash on unknown users, and applies IP + account rate limiting. | Returning distinct error codes revealing account existence. |
