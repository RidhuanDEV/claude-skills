# Shadow API — Specialist Scenario Benchmarks (`evaluations.md`)

Use these 10 graded scenarios to verify `/shadow-api` enforces contract ownership, idempotent retries, RFC 9457 error hygiene, bounded pagination, multi-protocol selection, presigned uploads, and zero-breakage evolution.

| ID | Scenario Prompt | Expected Modules | Pass Criteria (Must Include) | Fail Red Flags (`must_not`) |
| :--- | :--- | :--- | :--- | :--- |
| **API-EVAL-01** | Client retries `POST /api/v1/orders` after a 5s network timeout while an API v1->v2 migration is active. | `04`, `08` | Enforces `Idempotency-Key` stored with `(tenant_id, key, payload_sha256, state, response)` returning cached result on exact retry, `422` on payload mismatch, `409` on in-flight lock, and additive v1->v2 coexistence with RFC 9745 `Deprecation`/`Sunset`. | Creating duplicate orders on timeout retry or breaking v1 clients mid-migration. |
| **API-EVAL-02** | NestJS backend generates OpenAPI via `SwaggerModule`; developer wants to hand-edit generated `openapi.json`. | `01` | Runs `discover_api_artifacts` first, identifies Code-First ownership, updates NestJS DTOs/decorators and regenerates via project workflow instead of manually editing generated output. | Hand-editing generated OpenAPI output or creating a competing second spec file. |
| **API-EVAL-03** | User asks generically `"Buatkan dokumentasi API untuk proyek ini"` on a repo with zero maintained docs. | `01` | Asks immediately via interactive question tool offering compatible choices (Markdown reference, OpenAPI 3.1 contract, Postman/Bruno collection) and waits before creating persistent files. | Silently initializing random competing specs without resolving architectural ownership. |
| **API-EVAL-04** | API returns `{ "error": "PrismaClientKnownRequestError: Unique constraint failed on users_email_key", "stack": "..." }` with HTTP `200`. | `02` | Replaces with proper HTTP `409 Conflict` + RFC 9457 `application/problem+json` (`type`, `title`, `status`, `detail`, `instance`, `requestId`) with zero raw SQL/Prisma/stack trace exposure. | Returning HTTP `200` for errors or leaking ORM/SQL/stack traces in responses. |
| **API-EVAL-05** | `GET /api/v1/transactions?page=5000&limit=10000` causes full-table scan and duplicate/skipped rows as new rows arrive. | `03` | Replaces unbounded offset with keyset/cursor pagination (`after` opaque cursor + stable tie-breaker `(created_at DESC, id DESC)`) and enforces hard `limit <= 100`. | Allowing unbounded `limit=10000` or claiming `OFFSET 500000` scales cleanly under live writes. |
| **API-EVAL-06** | Mobile app uploads 40MB inspection videos via `POST /api/v1/upload` multipart buffered in Node.js RAM, causing OOM crashes. | `06` | Switches to direct-to-S3/R2 **short-lived presigned upload URL** with strict `content-length-range`, async magic-byte MIME verification, randomized UUID key, and `202 Accepted` processing status. | Buffering 40MB files in Node RAM or trusting client `Content-Type` header alone. |
| **API-EVAL-07** | GraphQL endpoint allows nested query `user { orders { items { order { user { ... } } } } }` (depth 15) and triggers 400 SQL queries per request. | `05` | Implements per-request **DataLoader** batching (`0` N+1), enforces max query depth (`<= 7`) + complexity/cost cap, persisted queries for prod, and field-level AuthZ checks. | Leaving GraphQL depth unbounded or running per-item DB queries inside resolvers. |
| **API-EVAL-08** | Team wants to drop `legacy_status` and make `tax_id` required on `POST /v1/invoices` next week for mobile clients still on app v1.2. | `08` | Flags both as breaking changes (`api_contract_verifier.py --check-breaking-diff`), mandates Expand-Contract / additive v2 path or optional default + RFC 9745 `Deprecation`/`Sunset` headers + consumer telemetry before removal. | Pushing breaking schema changes onto live v1 endpoints without deprecation window. |
| **API-EVAL-09** | Backend builds outbound customer webhooks; customer sets webhook URL to `http://169.254.169.254/latest/meta-data/`. | `06`, `07` | Signs outbound webhooks with dual-secret rotation `HMAC-SHA256` + timestamp AND resolves DNS upfront rejecting all private/link-local IPs (`169.254.169.254`, `127.0.0.1`, `10.0.0.0/8`, `::1`) with HTTPS-only policy. | Dispatching outbound webhooks without SSRF egress validation or cryptographic signatures. |
| **API-EVAL-10** | Agent spawns a local `tsx` dev server solely to verify 2 new endpoints via `test_api_endpoint`. | `07` | Runs bounded `L1` HTTP checks against only the affected routes, verifies status/payload contracts, and tears down the exact tracked PID (`resource_cleanup.py --cleanup-owned`) on exit without touching sibling servers. | Leaving orphan dev servers running or killing unrelated `node.exe` processes globally. |
