# Shadow Analytics — Specialist Scenario Benchmarks (`evaluations.md`)

Use these 13 graded scenarios to verify that an agent invoking `/shadow-analytics` operates at **Staff Product Analyst & Experimentation Engineer** rigor across all 5 capability layers (Domain Expertise, Architecture, Audit/Diagnosis, Statistical Verification, and Production Operations).

| ID | Scenario Prompt | Expected Modules | Pass Criteria (Must Include) | Fail Red Flags |
| :--- | :--- | :--- | :--- | :--- |
| **ANALYTICS-EVAL-01** | Define a North Star Metric, OEC, and guardrail hierarchy for a B2B SaaS workflow product; reject vanity DAU/pageviews. | `01` | Links NSM to delivered customer value (not logins/pageviews), decomposes metric tree into input levers, defines explicit latency/error/churn guardrails, assigns metric owners. | Recommending raw pageviews or total signups as NSM without retention or guardrail metrics. |
| **ANALYTICS-EVAL-02** | Design a typed tracking plan for an e-commerce checkout where `Cart_Item_Added` can fire 5 times for the same SKU and `Order_Completed` fires once per order. | `02` | Uses strict `Object_Action` naming, typed schema version, **occurrence-unique retry-stable `event_id` (UUIDv7)** for repeatable `Cart_Item_Added`, deterministic transition key ONLY for once-per-order `Order_Completed`, and zero raw PII. | Using `sha256(event + skuId)` for repeatable `Cart_Item_Added` (drops legitimate repeats). |
| **ANALYTICS-EVAL-03** | Users share a POS/clinic kiosk tablet and log in/out across shifts; analytics funnels are blending staff accounts together. | `03` | Calls `reset()` / rotates `anonymous_id` on logout, separates device/kiosk ID from user ID, prevents cross-user alias merging on shared terminals. | Calling `alias()` on every login without resetting `anonymous_id` on logout. |
| **ANALYTICS-EVAL-04** | A user submits a UU PDP / GDPR erasure request (`DSAR`). We use Postgres warehouse + PostHog + GA4 + Resend. Team proposes `DELETE FROM analytics_identity_map`. | `04` | Explicitly flags warehouse-only deletion as **non-compliant**, orchestrates vendor deletion APIs/SLAs across PostHog, GA4, and Resend, audits retention TTLs, and retains only keyed HMAC opt-out/suppression tombstones. | Claiming deleting `analytics_identity_map` alone satisfies UU PDP/GDPR. |
| **ANALYTICS-EVAL-05** | Client-side GA4 reports 18% fewer paid orders than Postgres `orders` table. Diagnose and architect reliable revenue analytics. | `05`, `06` | Attributes discrepancy to ad-blockers/ITP/browser unload drops, designates server-side truth for billing/revenue events, recommends first-party `/ingest` proxy for behavioral telemetry, and specifies dual-stream reconciliation by `event_id`. | Treating client-side browser events as source of truth for revenue. |
| **ANALYTICS-EVAL-06** | A mobile app release silently changed `price` from `number` to formatted string `"Rp 50.000"`, zeroing out the revenue dashboard. | `07` | Designs schema validation at ingestion, routes invalid payloads to quarantine/DLQ instead of silent drop or cast-to-0, adds freshness + null-rate + schema-drift alerts and CI tracking-contract tests. | Suggesting ad-hoc SQL regex parsing in BI dashboards as the sole fix. |
| **ANALYTICS-EVAL-07** | **Monarch Benchmark:** An A/B test shows **+12% checkout conversion lift (`p = 0.02`)**, but split check reveals **SRM (`p = 0.0002`)**. PM wants to ship today. | `11`, `15` | **BLOCKS ship decision (`BLOCKED_SRM`)** despite `p = 0.02`; explains why SRM invalidates causal inference (selection/logging bias can easily create fake +12% lift); runs structured SRM triage (trigger/assignment timing, bot filtering, redirect latency, client-side bucketing drops, cache key leak); requires root-cause fix + clean re-run before shipping. | Recommending "ship anyway because p=0.02 is significant" or "re-weight the groups post-hoc to fix SRM". |
| **ANALYTICS-EVAL-08** | Team wants to compare **Revenue per Session** and **Click-Through Rate per Impression** in a user-randomized experiment using a standard naive two-proportion Z-test. | `12` | Identifies unit-of-analysis (`session`/`impression`) vs unit-of-randomization (`user`) mismatch (intra-user correlation violates independence); selects **Delta Method** or cluster-level **Bootstrap** over randomization units. | Applying naive event-level Z-test on ratio metrics (deflates SE and inflates false positives). |
| **ANALYTICS-EVAL-09** | Engineer applies CUPED using `in_experiment_page_views` as the covariate to cut experiment runtime in half. | `12` | Rejects covariate immediately as **post-assignment leakage** (violates Deng et al. WSDM 2013 independence assumption and biases ATE); replaces with strictly **pre-experiment** metric from identical lookback window prior to randomization. | Approving any in-experiment variable as a CUPED covariate. |
| **ANALYTICS-EVAL-10** | PM peeks at fixed-horizon p-values every morning for 14 days and wants to stop on Day 4 when `p = 0.041`. | `13` | Explains peeking false-positive inflation (5% nominal alpha swells to ~20–30%); recommends **mSPRT (Always-Valid Inference)** or **Group Sequential Testing (O'Brien-Fleming / Lan-DeMets alpha spending)** pre-registered before launch, plus minimum 1–2 full weekly cycles for seasonality. | Allowing early stopping on fixed-horizon p-value without alpha adjustment. |
| **ANALYTICS-EVAL-11** | A ride-hailing / marketplace team runs a user-level 50/50 test on driver pricing incentives and observes a huge treatment win. | `13` | Detects **SUTVA / network interference** (treatment cannibalizes shared driver supply from control); recommends **geo/cluster randomization** or **time-based switchback designs** with cluster-robust inference. | Trusting user-level randomization in a capacity-constrained marketplace. |
| **ANALYTICS-EVAL-12** | Legal/regulatory change rolls out to Jakarta first and cannot be A/B tested; leadership asks for the causal impact on retention. | `14` | Selects quasi-experimental **Difference-in-Differences (DiD)** or **Synthetic Control**, explicitly tests **parallel pre-trends**, checks for concurrent confounders/spillovers, and reports uncertainty + honest non-causal caveats if parallel trends fail. | Presenting simple before-vs-after percentage delta as proven causal impact. |
| **ANALYTICS-EVAL-13** | Build an N-day vs unbounded retention cohort table and strict ordered checkout funnel in SQL without inflating drop-offs from out-of-order timestamps. | `08`, `09`, `10` | Distinguishes strict ordered vs unordered funnels with explicit conversion window, distinguishes N-day vs unbounded/rolling vs bracket retention, accounts for lifecycle states (`New/Retained/Resurrected/Churned`), and guards against Simpson's paradox across device/channel segments. | Confusing N-day retention with cumulative active users or omitting conversion windows. |
