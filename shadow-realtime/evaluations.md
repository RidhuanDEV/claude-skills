# `shadow-realtime` — Specialist Evaluation Scenarios

Use these offline evaluation scenarios to grade whether `shadow-realtime` operates as a **Realtime Transport & Client Synchronization Specialist** (transport ADR selection, `Last-Event-ID` resumption & dedup, multi-node fan-out, immediate mid-connection revocation, slow-consumer backpressure, reconnect storm jitter, and honest CRDT boundaries).

| ID | Scenario Prompt | Expected Specialist Behavior | Fail Red Flags |
| :--- | :--- | :--- | :--- |
| **RT-EVAL-01** | *"Kami butuh feed notifikasi server -> browser dan streaming token AI lewat proxy korporat Nginx/Cloudflare; tim langsung mau bangun cluster WebSocket custom."* | Evaluates transport trade-offs via ADR: recommends **SSE (`EventSource` + `Last-Event-ID`)** over WebSocket for unidirectional server->client streams (native HTTP/2 multiplexing, corporate proxy friendliness, built-in auto-reconnect cursor, requires `X-Accel-Buffering: no`) and reserves WebSocket strictly for true low-latency bidirectional frames. | Forces WebSocket infrastructure for a purely unidirectional feed without checking SSE or reverse-proxy buffering. |
| **RT-EVAL-02** | *"Klien mobile terputus selama 30 menit di lift, lalu reconnect ke stream notifikasi — sebagian event terlewat dan sebagian lainnya diterapkan dua kali."* | Designs monotonic per-stream sequence cursors (`Last-Event-ID`), bounded server replay buffer, client idempotent deduplication (`applied: false` on already-seen `seq`), and explicit `event: snapshot_required` full state resync when the client's cursor fell behind server retention — validated via `realtime_transport_verifier.py` (`trace_version: 2`). | Drops missed messages silently or replays frames blindly without client deduplication or expired-cursor snapshot fallback. |
| **RT-EVAL-03** | *"Admin mencabut akses karyawan dari tenant pada pukul 10:05, tetapi tab browser dengan koneksi WebSocket terbuka masih menerima seluruh pesan rahasia hingga jam 17:00."* | Identifies missing **Mid-Connection Auth Revocation** as a critical security breach; validates auth + tenant ACL at handshake AND broadcasts revocation control events across all gateway nodes (Redis/NATS Pub/Sub) + periodic lease checks so unauthorized sockets terminate or block immediately — verified via `realtime_transport_verifier.py`. | Checks JWT only during initial HTTP upgrade handshake and allows stale open sockets to keep receiving events until manual reload. |
| **RT-EVAL-04** | *"Setelah deploy rolling update, 40.000 klien WebSocket terputus bersamaan dan semuanya melakukan `setInterval(reconnect, 2000)` sehingga API gateway langsung tumbang DDoS."* | Diagnoses synchronized **Reconnect Thundering Herd**; replaces fixed 2s retry with **Exponential Backoff + Full Jitter** (`rand(0, min(30s, 500ms * 2^attempt))`), graceful server draining (`1001 Going Away` staggered waves), and connection rate admission limits. | Suggests only changing the fixed interval from 2s to 5s (still creates synchronized 40k waves!) without randomization jitter. |
| **RT-EVAL-05** | *"Satu pengguna di koneksi 2G yang macet menyebabkan buffer outbound WebSocket di server Node.js membengkak hingga `3GB` dan menumbangkan pod untuk semua pengguna lain."* | Implements bounded per-socket outbound queues (`maxBufferSize` + `bufferedAmount` checks), coalesces/drops droppable ephemeral frames (typing indicators, live cursors), and cleanly disconnects non-droppable slow consumers with resync code (`1008` / `snapshot_required`) so one stalled client cannot OOM the node. | Buffers unbounded outbound frames in RAM or tries to fix it solely by increasing container memory limits. |
| **RT-EVAL-06** | *"Kami menambah 3 replica backend di belakang load balancer, lalu user di Node 2 tidak menerima pesan chat yang dikirim user di Node 1."* | Identifies single-node in-memory `EventEmitter` trap; introduces horizontal **Multi-Node Pub/Sub Fan-Out** (Redis Pub/Sub/Streams or NATS) with tenant-scoped channels and verifies cross-node delivery (`publisher_node != receiver_node`) in a `topology: multi_node` trace via `realtime_transport_verifier.py`. | Suggests sticky sessions alone as a "fix" (sticky sessions keep one user on one node; they do NOT route messages between User A on Node 1 and User B on Node 2!). |
| **RT-EVAL-07** | *"Tim ingin memakai CRDT (`Yjs`) untuk menyinkronkan saldo dompet dan stok barang offline antar perangkat secara realtime."* | Blocks CRDT misuse on strong-consistency invariants; explains CRDTs (Yjs/Automerge) excel at collaborative rich text/canvas/presence (with periodic tombstone compaction), whereas **financial balances and limited inventory** require authoritative server-side transactional serialization (`shadow-domain`, `shadow-concurrency`). | Approves CRDT eventual convergence for bank balances or strict finite inventory decrements. |
