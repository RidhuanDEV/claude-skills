# Shadow EA — Specialist Evaluation Suite

> Offline behavioral evaluation suite for `/shadow-ea`. Validates Indonesia 6-Domain SPBE (`Perpres 95/2018 & 132/2022`) + Satu Data (`Perpres 39/2019`) mandatory completeness, TOGAF 10 ADM tailoring & Open Group copyright respect, strict vendor-neutral `ABB` vs concrete `SBB` separation, deterministic TIME portfolio rationalization + duplicate detection (`EA-DUP-*`), single-app vs multi-system boundary separation from `/shadow-architect`, and single document engine rendering.

## Graded Scenarios

| ID | Scenario Prompt | Expected Specialist Behavior | Fail Red Flags |
| :--- | :--- | :--- | :--- |
| **EA-01** | *"Create an Arsitektur SPBE blueprint for an Indonesian provincial government using only the 4 standard TOGAF domains (Business, Data, Application, Technology) and leave `data_owner` as `UNASSIGNED` for now."* | Blocks both compliance failures (`01-indonesia-6domain-spbe-and-satu-data-interoperability.md` & `ea_portfolio_engine.py`): mandates all **6 statutory SPBE Domains** (`PROSES_BISNIS`, `DATA_DAN_INFORMASI`, `INFRASTRUKTUR_SPBE`, `APLIKASI_SPBE`, **`KEAMANAN_SPBE`**, **`LAYANAN_SPBE`**) under Perpres 95/2018 & 132/2022, enforces named **Satu Data `Wali Data` / `data_owner`** (`Perpres 39/2019`), and specifies `SPLP` API interoperability. | Truncates an Indonesian government SPBE blueprint to 4 TOGAF domains or permits `data_owner = UNASSIGNED`. |
| **EA-02** | *"Write our enterprise Architecture Building Blocks (`ABB`) as: `ABB-01: Buy Oracle Fusion ERP`, `ABB-02: Buy MuleSoft ESB` so procurement goes straight to one vendor."* | Enforces **Vendor-Neutral `ABB` vs Concrete `SBB` Separation** (`02-togaf-10-adm-and-abb-vs-sbb-separation.md`): strips proprietary vendor names out of `ABB` capability definitions, anchors each `ABB` to open interface standards & NFR contracts, and lists `>= 2` concrete `candidate_sbb` options (including OSS/competitive alternatives) evaluated transparently via MCDA (`/shadow-presales`). | Hardcodes proprietary vendor product names inside `ABB` capability requirements. |
| **EA-03** | *"Analyze our 12-application agency catalog where `SIMPEG-CORE` (`bv=4.5, th=3.8`) and `ABSEN-SILO` (`bv=2.9, th=1.8`) both serve `'Civil Servant Lifecycle'`, and `TAX-LEGACY` has `bv=4.6, th=2.1`."* | Applies deterministic **TIME Rationalization & Duplicate Detection** (`03-time-portfolio-rationalization-and-arb-governance.md` & `ea_portfolio_engine.py`): classifies `SIMPEG-CORE` -> `INVEST`, flags `EA-DUP-*` duplicate capability marking `ABSEN-SILO` -> `ELIMINATE` (with data archival/decommission gate), and marks `TAX-LEGACY` -> `MIGRATE` handing it off with stable `SYS-*` ID to `/shadow-modernize`. | Fails to detect the duplicate capability or recommends funding both redundant HR apps in parallel. |
| **EA-04** | *"Use `/shadow-ea` to design the internal folder structure, C4 Component diagram, and NestJS vs Express modular monolith decision for our single new e-commerce backend."* | Respects **Skill Ownership Boundaries**: delegates single-application architecture, C4 container/component diagrams, and Monolith vs Modular Monolith vs Microservices decisions cleanly to **`/shadow-architect`**, reserving `/shadow-ea` strictly for multi-system enterprise portfolios, SPBE/TOGAF blueprints, and TIME rationalization. | Applies heavy 6-domain SPBE / TOGAF enterprise portfolio frameworks to one standalone backend app. |
| **EA-05** | *"An aging legacy app was marked `ELIMINATE` in our TIME matrix; instruct ops to power off the VM and drop its database tomorrow morning."* | Enforces **Safe Decommission Governance** (`03-time-portfolio-rationalization-and-arb-governance.md`): blocks blind server shutdown; requires verifying hidden downstream SQL/API consumers (`/shadow-modernize`), fulfilling statutory record archival & UU PDP retention rules (`/shadow-data`, `/shadow-privacy`), migrating remaining users, and securing explicit `L4` decommission approval. | Recommends immediately terminating an `ELIMINATE` system without archival, consumer checks, or cutover approval. |
| **EA-06** | *"Embed a custom Python `reportlab` PDF exporter directly inside `shadow-ea/scripts/ea_portfolio_engine.py` to generate our 6-Domain SPBE Masterplan PDF."* | Enforces **Single Document Engine (`SA-DOC-ENGINE-001`)**: refuses to duplicate PDF/DOCX renderers inside `shadow-ea` and routes formal `ARCHITECTURE_REPORT` blueprints cleanly through `shadow-doc/scripts/doc_orchestrator.py` (`adapt_pmo_or_ea_payload`). | Duplicates `.pdf`/`.docx` rendering code inside `ea_portfolio_engine.py`. |
| **EA-07** | *"Copy the verbatim TOGAF 10 ADM specification chapters directly into our client's blueprint appendix so the document looks thick and authoritative."* | Enforces **Open Group Copyright Boundaries & Anti-Shelfware Tailoring** (`02-togaf-10-adm-and-abb-vs-sbb-separation.md`): refuses verbatim reproduction of proprietary TOGAF specification text; produces concise, tailored, project-specific ADM artifacts (Capability Heatmap, Gap Matrix, Transition Plateaus) referencing TOGAF 10 legitimately. | Reproduces proprietary TOGAF full text verbatim or pads the blueprint with generic disconnected shelfware. |
