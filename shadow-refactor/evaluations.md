# `shadow-refactor` — Specialist Evaluation Scenarios

Use these offline evaluation scenarios to grade whether `shadow-refactor` enforces **Characterization Tests Before Edits**, **Strict Behavioral Equivalence (Zero Silent Validation/Rounding Changes)**, **Local Precedent Preservation**, **Side-Effect Ordering**, and **`L1` vs `L2` Scope Discipline**.

| ID | Scenario Prompt | Expected Specialist Behavior | Fail Red Flags |
| :--- | :--- | :--- | :--- |
| **REF-EVAL-01** | *"File legacy `billing/calculator.ts` (450 baris) belum punya unit test sama sekali; langsung saja kita rewrite bersih dari nol supaya modern."* | Treats missing tests as **HIGH RISK** (never license to rewrite blind!): inspects 1–3 closest repo precedents, locks exact observable behavior including existing rounding/error quirks into a passing **Characterization (Golden Master) Test** BEFORE touching production code, then extracts narrow seams incrementally (`refactor_characterization_gate.py`). | Rewrites the 450-line legacy file from scratch without baseline characterization tests. |
| **REF-EVAL-02** | *"Saat memisahkan helper kalkulasi diskon di `orders/pricing.ts`, saya lihat kode lama pakai `Math.floor` jadi sekalian saya ganti ke `Math.round` dan ubah batas minimum order dari 10.000 ke 15.000."* | Blocks silent behavioral drift (`silent_contract_changes` in `refactor_characterization_gate.py`): preserves exact legacy rounding (`Math.floor`) and validation thresholds during pure refactoring; separates intentional bug fixes or spec changes into an explicit follow-up commit with stakeholder approval! | Silently modifies rounding semantics or validation thresholds inside a "refactor" PR. |
| **REF-EVAL-03** | *"Untuk mempercepat fungsi `completeOrder`, ubah saja `await db.saveAndCommit(); await mailer.enqueueWebhook();` menjadi `await Promise.all([db.saveAndCommit(), mailer.enqueueWebhook()])`."* | Blocks reordering side effects: detects that `Promise.all` fires the external webhook concurrently BEFORE the DB transaction commits (sending customer webhooks for failed/rolled-back orders!); locks exact `DB_COMMIT -> EVENT_PUBLISH` ordering in characterization tests. | Parallelizes dependent DB commit and external side-effect notification during refactoring. |
| **REF-EVAL-04** | *"Monolith controller ini memanggil `Date.now()` dan `stripeClient` langsung di tengah kalkulasi sehingga tidak bisa di-unit-test; bagaimana memecahnya tanpa mengubah signature endpoint?"* | Introduces narrow **Seam / Port Injection** (`Clock`, `PaymentPort` with default production binding so existing callers don't break!), extracts pure domain logic into a deterministic module matching local conventions, and proves identical output before and after via characterization tests. | Breaks all external callers' signatures or introduces an unapproved heavy DI framework (`inversify`/`tsyringe`). |
| **REF-EVAL-05** | *"Kita perlu mengganti algoritma routing gudang di jalur produksi berisiko tinggi tanpa downtime dan tanpa big-bang cutover."* | Applies **Branch-by-Abstraction** (introduce narrow abstraction seam -> adapt existing implementation -> add candidate implementation behind shadow verification comparing old vs new outputs on production-like fixtures -> cut over -> clean old implementation only after parity is proven). | Deletes the working algorithm in-place and deploys the brand-new algorithm in a single unverified big-bang diff. |
| **REF-EVAL-06** | *"Tolong rapikan modul `invoices/parser.ts` — sekalian reformat 18 file lain di repo, hapus helper di folder `users/`, dan tukar `file:../sdk/sso-client` ke library npm baru."* | Enforces **`L1` vs `L2` Scope Discipline & SDK Preservation**: restricts edits and dead-code cleanup strictly to `invoices/parser.ts` (and its characterization test), blocks collateral edits to 18 unrelated files (`out_of_scope` in `refactor_characterization_gate.py`), and preserves local SSO SDKs and repo conventions (`L2` approval required for broader cleanup). | Reformats unrelated files, alters other modules, or swaps dependencies opportunistically during a scoped refactor. |
| **REF-EVAL-07** | *"Direktur minta analisis bisnis TCO 5 tahun apakah ERP 12 tahun kita sebaiknya Strangler Fig atau Full Rewrite dari nol."* | Recognizes ownership boundary and routes the business-case due diligence & TCO modeling cleanly to **`/shadow-modernize`** (while keeping `shadow-refactor` strictly for behavior-preserving incremental code evolution). | Writes a 5-year TCO modernization business case inside `shadow-refactor` without routing to `/shadow-modernize`. |
